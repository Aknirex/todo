# Agent Brief — 搜索输入框高度不足、文本裁切

> *This was generated by AI during triage.*

**Category:** bug
**State:** ready-for-agent
**Summary:** 安卓上搜索输入框高度不足，占位符/输入文本被纵向裁切显示不全

**Current behavior:**
搜索页的输入框（`.search-input`）只有 `padding: 22rpx 0` 和 `font-size: 28rpx`，没有显式 `height` 和 `line-height`；主页搜索浮层里的输入框（`.input-bar input`）同样是 `padding: 16rpx 24rpx` + `font-size: 28rpx` 且无高度约束。在安卓 app-plus 的原生 input 渲染下，文本行高与控件高度不匹配时会出现纵向裁切——占位符（"搜索任务标题、详情或标签..."）和输入中的多字节文本（中文）显示不全。该问题已在代码层面定位到强疑似路径，但需真机复现确认最终表现。

**Desired behavior:**
- 搜索页与主页搜索浮层的输入框：单行显示，显式高度与行高匹配，占位符和输入文本（含中文）完整可见、垂直居中
- 输入状态（focus）下高度不跳动、不裁切
- 清除按钮（×）与放大镜图标保持垂直对齐

**Key interfaces:**
- 搜索页 `.search-input` 样式 — 增加显式 `height` 与 `line-height`（建议以 96rpx 量级为基准，与相邻图标、按钮对齐）
- 主页搜索浮层 `.input-bar input` 样式 — 同样处理
- 其他输入框（详情页 `.field-input`、新建浮层标题输入）不在本次范围，但改动时注意不要破坏现有布局节奏

**Acceptance criteria:**
- [ ] 安卓真机：搜索页占位符完整显示，无纵向裁切
- [ ] 安卓真机：输入中英文混合文本（如"买牛奶 milk"），文本完整可见且垂直居中
- [ ] 安卓真机：输入较长关键词时右侧清除按钮不遮字、图标对齐正常
- [ ] 主页搜索浮层输入框同样满足以上三项
- [ ] H5 显示与修复前一致（无回归）
- [ ] 若真机无法复现裁切，需报告实际表现并说明结论，再决定是否合入高度调整

**Out of scope:**
- 多行输入支持（保持单行）
- 搜索框以外的输入框样式统一改造（如详情页/设置页，另立问题）
- 键盘弹出遮挡问题
