# Agent Brief — 修改待办项无法保存

> *This was generated by AI during triage.*

**Category:** bug
**State:** ready-for-agent
**Summary:** 详情页编辑待办后，只有点页面内返回箭头才保存；安卓系统返回键/手势返回时改动全部丢失

**Current behavior:**
详情页编辑标题、优先级、日期、标签、详情后，保存动作只挂在页面内返回箭头的点击处理（`goBack`）里 —— 该函数把表单数据传给 `todoStore.updateTodo` 后 `uni.navigateBack()`。安卓的硬件返回键和全面屏手势返回会直接弹出页面，不经过 `goBack`，因此用户编辑内容全部丢失。页面上没有保存按钮，也没有生命周期钩子（`onUnload`/`onHide`/`onBackPress`）兜底（全库 grep 无任何命中）。`updateTodo` 本身（store + repository 链路）逻辑正常，问题只在"触发时机"。

**Desired behavior:**
无论以何种方式离开详情页，未保存的编辑都必须持久化：

- 点页面内返回箭头 —— 保存后返回（现状保留）
- 安卓硬件返回键 —— 先保存再返回
- 全面屏手势返回 —— 先保存再返回
- 其他离开路径（如从详情页再跳转其他页、应用切后台后回收）不丢失编辑

**Key interfaces:**
- 详情页生命周期：`@dcloudio/uni-app` 的 `onUnload`（页面卸载）、`onBackPress`（安卓返回键拦截，可返回 false 放行系统返回）；手势返回在小程序/H5 的表现按平台处理，优先保证 app-plus 安卓
- `todoStore.updateTodo(id, UpdateTodoInput)` — 现有更新入口，幂等；已删除的待办（`deleted === true` 或 store 中不存在）应跳过保存，避免"删除后又被保存逻辑复活"
- 表单状态 `form`（title/priority/dueDate/tags/detail）— 保存时全量提交
- 撤销栈 `undoStore`：保存产生的 update 记录应保持现有语义（与 `goBack` 路径一致），撤销仍可用

**Acceptance criteria:**
- [ ] 安卓真机：修改标题 → 按系统返回键 → 回到列表，重进详情页改动仍在
- [ ] 安卓真机：修改详情 → 手势返回 → 改动仍在
- [ ] 安卓真机：点页面内返回箭头 → 改动仍在（回归）
- [ ] 删除待办（走删除确认弹窗）→ 返回后该待办不因保存逻辑复活
- [ ] 保存后使用撤销功能，恢复的是保存前的旧值（与现有 `goBack` 路径的撤销行为一致）
- [ ] 未做任何修改就返回时，不产生多余的 update 记录（或产生空操作记录可接受，需在实现中说明取舍）

**Out of scope:**
- 增加显式"保存"按钮或改动详情页 UI 布局
- 编辑中字段的实时自动保存（本次只要求离开时保存）
- 待办在保存前已被其他端删除的冲突处理（store 中找不到即跳过即可）
