# Agent Brief — 新建待办不聚焦详情输入框

> *This was generated by AI during triage.*

**Category:** bug
**State:** ready-for-agent
**Summary:** 点击主页 FAB 新建按钮打开浮层后，详情输入框没有自动聚焦，用户需手动点击才能输入

**Current behavior:**
主页右下 FAB（`openNewTask`）打开"新建任务"浮层后，没有任何输入框获得焦点。标题输入框绑定了 `@confirm="focusDetail"`，但该处理函数是空实现（仅注释"由组件自动处理"），按下键盘确认键也不会把焦点移到详情框。详情 `textarea` 上有 `ref="newDetailRef"` 但脚本从未使用 —— 说明聚焦是计划内功能，未实现。

**Desired behavior:**
- 点击 FAB 打开新建浮层时，详情输入框（textarea）自动聚焦并唤起键盘（安卓）
- 在标题输入框按键盘"确认/下一步"时，焦点移动到详情输入框
- 打开浮层的重置逻辑（清空标题、详情、优先级等）保持现状

**Key interfaces:**
- 新建浮层的 `newTaskOpen` 状态（控制显示）与详情 `textarea`（`ref="newDetailRef"`，`v-model="newDetail"`）— 打开浮层后（`uni.nextTick` 之后）触发聚焦，可用 uni-app 的 `focus` prop 或 `$refs` 调用
- 标题输入框的 `@confirm="focusDetail"` 处理函数 — 实现为"聚焦详情输入框"，与打开浮层时的行为一致
- 关闭浮层（取消/创建成功）时应清理焦点，避免键盘残留

**Acceptance criteria:**
- [ ] 安卓真机：点 FAB → 浮层打开，详情输入框自动聚焦且键盘弹出，可直接输入
- [ ] 安卓真机：在标题框输入后按键盘确认键，焦点切到详情输入框
- [ ] 浮层内手动点击其他区域（优先级、标签、日期）后，焦点行为不异常（例如点标签输入框时不再抢焦点到详情框）
- [ ] 取消或创建成功后关闭浮层，键盘收起、无聚焦残留
- [ ] H5 上行为合理（自动聚焦可用则一致，键盘行为按平台差异可接受）

**Out of scope:**
- 搜索浮层、设置页等其他输入框的自动聚焦
- iOS 键盘遮挡输入框的滚动处理
