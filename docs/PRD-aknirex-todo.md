## 1. Summary（概要）

aknirex-todo 是一款面向中文互联网用户的极简 AI todo 应用。核心亮点是**任务双向转换**：用户粘贴一段聊天记录，AI 自动拆解为结构化待办；反过来，AI 也能把散乱的待办整理成清晰的文本。应用基于 UniApp 跨端框架，首版覆盖微信小程序（手机 + PC）和 Android App，所有数据本地存储，用户自带 LLM API Key（BYOK 模式），首版即开放第三方 Agent API。

## 3. Background（背景）

### 3.1 这是什么？

一款免费的 todo 应用，但不只是清单工具。它是**用户与 AI 之间的任务双向转换器**：

- **说进来**：把微信聊天、会议记录、口头交代中的碎片文字变成清晰的待办
- **理出来**：把散乱的待办整理成有结构的文本，用于汇报、周报、理清思路

### 3.2 为什么现在做？

| 因素 | 说明 |
|------|------|
| **LLM 能力成熟** | DeepSeek、小米 Mimo 等国产模型价格极低（约 ¥0.001/次），BYOK 模式在技术上可行 |
| **微信小程序生态** | PC 微信已原生支持小程序，一套代码可同时覆盖手机和 PC |
| **现有工具的缺口** | Todoist/TickTick 收费、无 AI；ChatGPT/Claude 无法直接管理待办；国内缺乏免费 + AI + 本地隐私的组合 |
| **Agent 生态空白** | 目前没有开放 Agent API 的 todo 应用，先发者定义标准 |

### 3.3 最近有什么变化？

- UniApp 跨端框架成熟，一套代码发布微信小程序 + Android App
- Cloudflare Workers 免费层足够支撑同步中继（v1.1）
- 国产 LLM API 价格降至极低水平，BYOK 模式用户成本可忽略

## 5. Market Segment(s)（市场细分）

### 5.1 细分 1：信息流打工人（Beachhead Segment）

**JTBD**：当我在微信群/钉钉/飞书收到碎片化的任务指令时，我想**瞬间将这些碎片转成可追踪的待办**，以便不漏掉任何任务。

| 维度 | 描述 |
|------|------|
| 场景 | 日常工作依赖即时通讯工具接收任务（领导指示、甲方需求、跨部门协作） |
| 痛点 | 聊天记录里藏着待办，反复翻阅查找；手动整理太慢；手机录入、PC 查看时数据不通 |
| 为什么是第一个 | 微信小程序的主场场景——任务在微信中产生，在微信中完成转换，切换成本最低 |

**约束**：
- 用户可能不熟悉 LLM API Key 配置 → 需要入门引导
- 微信小程序有包体大小限制 → 首版功能需精简
- 个人开发主体审核 AI 类目可能有风险 → 需准备 H5 备用方案

### 5.2 细分 2：信息整理需求者

**JTBD**：当我手头堆了几十个待办、却看不清全局时，我想**让 AI 帮我梳理成清晰的文本**，以便用于汇报、写周报、理清执行思路。

| 维度 | 描述 |
|------|------|
| 场景 | 需要定期向他人或自己汇报进度，或面对大量任务时需要结构化梳理 |
| 痛点 | 现有 todo 工具只能"看"，不能"讲"；导出为文本需要大量手工整理 |
| 优先级 | 次要——依赖于已有足够多的 todo 数据后才产生价值（冷启动后） |

### 5.3 细分 3：第三方 Agent 构建者

**JTBD**：当我的 AI 应用需要操控用户的 todo 列表时，我想**接入一个标准化、开放的任务接口**，以便在自己的 Agent 中集成任务管理能力。

| 维度 | 描述 |
|------|------|
| 场景 | LLM Agent 开发者（企业内部自动化、个人助手开发者、AI 工作流工具） |
| 痛点 | 现有 todo 工具要么没有 API，要么接口非标准化，要么不允许第三方操控 |
| 首版即支持 | 开放 API 是生态策略的核心——从第一天起建立 |

## 7. Solution（解决方案）

### 7.1 UX / 用户流程

#### 核心流程 1：文本 → Todo 拆解

```
用户打开小程序
    ↓
进入 Agent 对话界面
    ↓
粘贴一段文本（聊天记录/会议纪要/任务描述）
    ↓
点击"拆解"按钮
    ↓
Agent 分析文本，生成结构化 todo 列表预览
    ↓
用户确认/编辑/删除部分条目
    ↓
一键保存到当前列表
```

#### 核心流程 2：Todo → 文本总结

```
用户打开一个 todo 列表
    ↓
点击"总结"按钮
    ↓
Agent 分析所有条目（标题、优先级、标签、截止日期）
    ↓
生成连贯的任务汇总文本
    ↓
用户可编辑文本
    ↓
复制/导出/分享
```

#### 核心流程 3：快速创建 Todo

```
用户在列表页点击"+"按钮
    ↓
输入一行标题（可为空）
    ↓
选择优先级（默认中等，可切换高/低）
    ↓
点击确认
    ↓
Todo 创建完成（可选：补充截止日期、标签、详情）
```

#### 核心流程 4：BYOK 配置（首次使用）

```
用户首次点击 Agent 功能
    ↓
检测未配置 API Key
    ↓
展示引导页面（DeepSeek / 小米 Mimo 图文指引）
    ↓
用户按指引注册、获取 Key
    ↓
粘贴 Key 到配置页
    ↓
配置完成，可使用 Agent 功能
```

### 7.2 Key Features（功能规格）

#### 7.2.1 Todo 项（核心实体）

**数据模型**：

| 字段 | 类型 | 必填 | 默认值 | 约束 |
|------|------|------|--------|------|
| id | string | 自动生成 | UUID | 不可修改 |
| title | string | 否 | 空 | 最大 500 字符 |
| priority | enum | 是 | medium | high / medium / low |
| dueDate | date | 否 | null | ISO 8601 格式 |
| tags | string[] | 否 | [] | 自由文本，无预定义 |
| detail | string | 否 | 空 | 多行文本，最大 5000 字符 |
| completed | boolean | — | false | 可切换 |
| createdAt | datetime | 自动生成 | 当前时间 | 不可修改 |
| updatedAt | datetime | 自动更新 | — | 每次修改自动更新 |
| listId | string | 是 | 默认列表 ID | 关联到所属列表 |

**操作规格**：

| 操作 | 前置条件 | 后置条件 | 边界情况 |
|------|----------|----------|----------|
| 创建 | 无 | 新 todo 插入本地数据库，操作记入 Undo Stack | title 为空时允许创建；priority 必须有值 |
| 编辑 | todo 存在 | 更新 updatedAt，操作记入 Undo Stack | 所有字段均可修改，包括 listId（移动到其他列表） |
| 删除 | todo 存在 | 从数据库标记删除（软删除），操作记入 Undo Stack | 删除后可通过撤销恢复 |
| 切换完成 | todo 存在 | completed 取反，updatedAt 更新，操作记入 Undo Stack | 无 |

#### 7.2.2 Todo 列表

**数据模型**：

| 字段 | 类型 | 必填 | 默认值 | 约束 |
|------|------|------|--------|------|
| id | string | 自动生成 | UUID | 不可修改 |
| name | string | 否 | "默认列表" | 最大 100 字符 |
| createdAt | datetime | 自动生成 | 当前时间 | 不可修改 |
| isDefault | boolean | — | false | 仅一个列表可为 true |

**操作规格**：

| 操作 | 前置条件 | 后置条件 | 边界情况 |
|------|----------|----------|----------|
| 创建 | 无 | 新列表插入数据库 | name 为空时使用默认名称 |
| 编辑 | 列表存在 | 更新 name | 不可修改 isDefault |
| 删除 | 列表存在且非默认 | 列表及其下所有 todo 标记删除，操作记入 Undo Stack | 默认列表不可删除 |

#### 7.2.3 全局搜索与筛选

**搜索规格**：
- 搜索范围：所有列表中的 todo
- 搜索字段：title、detail、tags
- 搜索方式：模糊匹配（包含关键词即命中）
- 搜索结果：按匹配度排序，高亮匹配关键词

**筛选规格**：

| 筛选维度 | 可选值 | 支持组合 |
|----------|--------|----------|
| 优先级 | high / medium / low | 是 |
| 标签 | 用户自建的所有标签 | 是（多选） |
| 完成状态 | 已完成 / 未完成 | 是 |
| 截止日期 | 今天 / 本周 / 本月 / 逾期 / 无截止日期 | 是 |
| 所属列表 | 所有列表名 | 是 |

#### 7.2.4 全局撤销

**规格**：
- 撤销深度：≥ 50 步历史
- 撤销范围：所有操作（创建/编辑/删除/完成/列表操作）
- 撤销方式：全局撤销按钮，每次点击撤销最近一步操作
- 撤销栈满时：丢弃最早的操作记录

**Undo Stack 数据结构**：

```typescript
interface UndoAction {
  id: string;
  type: 'create' | 'update' | 'delete' | 'toggle_complete' | 'move';
  entityType: 'todo' | 'list';
  entityId: string;
  before: Partial<Todo | List>;  // 操作前状态
  after: Partial<Todo | List>;   // 操作后状态
  timestamp: number;
}
```

#### 7.2.5 内置 Agent（BYOK 模式）

**LLM 配置**：

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| provider | LLM 提供商 | — |
| apiKey | 用户的 API Key | — |
| baseUrl | API 基础 URL | 提供商默认值 |
| model | 使用的模型 | 提供商默认值 |

**支持的提供商（首版）**：

| 提供商 | 接口类型 | 推荐理由 |
|--------|----------|----------|
| DeepSeek | OpenAI 兼容 | 国内首选，价格极低，申请简单 |
| 小米 Mimo | OpenAI 兼容 | 小米生态用户便利 |
| 其他 OpenAI 兼容 | OpenAI 兼容 | 覆盖最多提供商 |

**Agent 能力 1：文本 → Todo 拆解**

| 项目 | 规格 |
|------|------|
| 输入 | 用户提供的自然语言文本（最大 10,000 字符） |
| 输出 | 结构化 todo 列表（JSON 格式），包含 title、priority、tags |
| 处理流程 | 1. 构建 system prompt + 用户文本 → 2. 调用 LLM API → 3. 解析 JSON 响应 → 4. 展示预览 → 5. 用户确认后保存 |
| 错误处理 | API 超时（30 秒）→ 提示重试；响应格式错误 → 重试一次；Key 无效 → 提示重新配置 |

**Agent 能力 2：Todo → 文本总结**

| 项目 | 规格 |
|------|------|
| 输入 | 当前列表的所有 todo 项（标题、优先级、标签、截止日期、完成状态） |
| 输出 | 连贯的任务汇总文本（中文） |
| 处理流程 | 1. 构建 system prompt + todo 数据 → 2. 调用 LLM API → 3. 展示文本 → 4. 用户可编辑 → 5. 复制/导出 |
| 可选上下文 | 用户可附加额外说明（如"用于周报"、"汇报给领导"） |

#### 7.2.6 第三方 Agent API

**接口规范**：

| 项目 | 规格 |
|------|------|
| 协议 | RESTful HTTP API |
| 认证 | API Key（请求头 `X-Api-Key`） |
| 限流 | 按 API Key 限流，具体阈值待技术方案确定（建议：100 次/分钟） |
| 数据格式 | JSON |
| 错误码 | 标准 HTTP 状态码 + 自定义错误码 |

**公开接口清单**：

| 接口 | 方法 | 路径 | 说明 |
|------|------|------|------|
| 创建 todo | POST | /api/v1/todos | 创建单个 todo |
| 获取 todo | GET | /api/v1/todos/:id | 获取单个 todo 详情 |
| 更新 todo | PATCH | /api/v1/todos/:id | 更新 todo 字段 |
| 删除 todo | DELETE | /api/v1/todos/:id | 删除 todo |
| 列表 todo | GET | /api/v1/todos | 按条件列出 todo（支持筛选参数） |
| 切换完成 | POST | /api/v1/todos/:id/toggle | 切换完成状态 |
| 列出列表 | GET | /api/v1/lists | 获取所有列表 |
| 获取列表 | GET | /api/v1/lists/:id | 获取列表详情及 todo |
| 搜索 | GET | /api/v1/search?q= | 全局搜索 |
| 撤销 | POST | /api/v1/undo | 撤销最近操作 |
| 批量创建 | POST | /api/v1/todos/batch | 批量创建 todo（Agent 拆解用） |

**微信小程序端 API 约束**：

小程序不支持监听 TCP 端口，第三方 Agent 无法直接连接。候选方案：

| 方案 | 可行性 | 优先级 |
|------|--------|--------|
| Android 端代理 | Android App 作为 API 服务端，局域网内可访问 | 首选 |
| 云端 Webhook 回调 | 需要云端服务器，增加运维成本 | 备选 |
| WebSocket 服务 | 需要 uni-app 插件支持 | 待评估 |

| 小米 Mimo | API Key 申请步骤、额度获取方式 | 图文指引页面 |
| 通用配置 | base_url + key 配置方式 | 表单 + 说明 |

**引导触发时机**：首次使用 Agent 功能时，检测未配置 Key，自动展示引导页。

### 7.3 Technology（技术选型）

| 层级 | 选型 | 理由 |
|------|------|------|
| 跨端框架 | UniApp | 一套代码发布微信小程序 + Android App |
| 状态管理 | Pinia | UniApp 官方推荐，支持 Vue 3 Composition API |
| 本地存储 | SQLite（uni-app 插件） | 结构化数据存储，支持复杂查询 |
| LLM 调用 | OpenAI 兼容接口 | 覆盖最多提供商，统一适配层 |
| Agent API | RESTful + API Key | 标准化，第三方易接入 |
| 同步中继（v1.1） | Cloudflare Workers + Durable Object | 免费、全球部署、WebSocket 支持 |

### 7.4 Assumptions（假设）

| # | 假设 | 重要性 | 验证方式 |
|---|------|--------|----------|
| H1 | 用户面对碎片化文本时，有足够的动力切换到小程序"拆解" | 🔴 核心 | 观察早期用户行为；访谈 |
| H2 | 用户的 LLM API Key 拥有率足够高，或在引导下愿意注册 | 🔴 核心 | 问卷调查；引导流程配置完成率 |
| H3 | Agent 拆解结果质量（准确度、优先级判断）能达到用户可接受水平 | 🟡 重要 | 内部 Prompt 迭代 + 种子用户反馈 |
| H4 | 微信小程序审核能通过（个人主体，AI 类目） | 🟡 重要 | 提前提交审核；准备 H5 备用 |
| H5 | "免费"是足够强的选择理由，能促使用户迁移 | 🟡 重要 | 竞品用户访谈 |
| H6 | 加密 WebSocket 中继的同步体验能满足用户期望（v1.1） | 🟡 重要 | Worker 原型验证延迟与配对 |
| H7 | Agent API 能在 3 个月内吸引至少 5 个活跃第三方开发者 | 🟡 重要 | 跟踪接入数；开发者访谈 |
| H8 | 入门引导能显著提升 Key 配置完成率 | 🟡 重要 | A/B 测试 |

**H2 风险缓解**：
- 入门引导页降低注册门槛
- 首推 DeepSeek（注册即送额度，流程最短）
- 费用透明化（"每次拆解约 ¥0.002"）
- 支持多 Provider 切换
- 降级方案：无 Key 时仍可使用纯手动 todo 功能
